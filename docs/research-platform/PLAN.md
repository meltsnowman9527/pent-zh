## 1. 目标、范围与成功标准


### 1.1 目标

在现有 PentAGI 上建成面向授权测评的研究平台：以"漏洞收集 → 资产发现与定向扫描 → 利用链推理 → 多 Agent 渗透验证 → 报告输出"为主线，把资产、漏洞知识、候选利用链、受控验证与证据串成一个可演示、可追溯、可复算的完整流程；用户可配置智能体能力（Skill/MCP），可用分步、自动、助手三种方式驱动同一流程。

### 1.2 范围外（本方案不承诺）

科研实验与指标统计、论文、真实铁路专有协议主动探测、生产环境高风险验证、破坏性动作（R4 不执行）、机器学习模型训练、靶场部署（独立环境）、多副本/分布式部署。

### 1.3 成功标准（可验收）

1. 五个业务页面 + 任务中心可从第一页走到最后一页，跨页切换/刷新/深链接不丢范围；
2. 自动执行模式一键跑完七个阶段（按五页呈现），遇审批点暂停并可中途接管；交互助手模式可驱动同样的阶段并产出落库；
3. 知识图谱可视化（三条关系链 + 链/证据关系），可由 PostgreSQL 重建；
4. 精度夹具全绿：版本比较三生态、资产归并冲突场景、候选匹配别名与缺失、利用链合成图、七类验证结论、确定性（关模型仍可出路径）；
5. 证据链完整：原文不可变 + SHA-256 + 来源/解析版本可追溯，报告缺证据不可发布，断模型可重建报告；
6. 零容忍项测试为 0：越权目标、禁止动作、由测试引起的服务中断；
7. 既有功能不退化：Flow、助手、知识库、资源、模板、模型服务、报告导出、中文化、P0 生命周期全部保留。

### 1.4 未来扩展影响记录（本轮不实现）

按 D1，本轮不做实验指标。下表只记录"如果以后反转决定，需要动什么、代价在哪"，**不产生任何当前接口、字段或占位代码**：

| 项目 | 本轮决定 | 反转时需要补的东西 |
|---|---|---|
| 人工工时/活动埋点 | 不做（不建 `activity_log`） | 新增 `activity_log`（主体、阶段、活动类型、分钟数、对象 ID）并在各阶段入口写点；事后日志无法重建，若需历史数据只能补做实验 |
| 真值与证据门槛标记 | 不做（`ground_truth_ref` 不进入业务迁移） | 在 `asset_vulnerabilities` 上加真值/证据门槛列与判定规则；已有数据需重新判定 |

## 2. 总体架构


### 2.1 主线与依赖方向


```
(K) 漏洞收集与知识图谱   ← 常驻服务：外部定时采集 + 用户上传 + 图谱 + 检索
        │  （K 可随时更新并触发 M 重算；A 可独立先运行）
        │
(A) 资产发现            ← 被动流量为主 + 主动最小化补全；或传统主动发现
        ▼
(M) 疑似资产-漏洞集合    ← A × K：产品组件 → 版本范围 → 服务/配置条件
        ▼
(S) 定向漏洞扫描         ← 共享检测项 + 漏洞专用检测 → 三态判定
        ▼
(R) 利用链推理           ← 事实快照 → 有界搜索 → 剪枝 → 可信度/风险分项
        ▼
(V) 多 Agent 受控验证    ← 验证任务图 → 能力选择 → 网关放行 → 证据判定 → 七类结论
        │
        └─ 反馈：缺失资产/漏洞/条件 → 回 A / K / M / R（限次，见 §3.7）
        ▼
(P) 报告输出            ← 结构化装配 + 模型叙述 + 证据附录 + 发布门禁
```

运行依赖为 A 与 K 独立准备、M 同时引用 A×K 的指定版本，随后 S→R→V→P。K 是持续服务，任务里的 K 表示选用/生成一个知识快照；采集永不结束不会阻塞任务。无发现、无链或受限未验证时仍可生成说明完整的报告，跳过状态须经依赖规则审核。

页面顺序按 D5：漏洞收集与知识图谱 / 资产发现与漏洞扫描 / 利用链推理 / 渗透测试 / 报告输出。M 与 S 合并在一页（左：疑似集合与确认状态；右：扫描计划与证据）。

**计数口径**：业务阶段共七个（K 漏洞收集 / A 资产发现 / M 疑似集合 / S 定向扫描 / R 利用链推理 / V 受控验证 / P 报告输出），界面按五页组织（M 与 S 合并）；任务中心、审批、审计、能力管理是辅助页面。本文中"五阶段/五页"一律指界面口径，"七阶段"指阶段行口径。

### 2.2 三个入口，一份状态


一个 `research_task` 下挂阶段行；阶段状态、产物、证据引用全部存 PostgreSQL，**阶段完成由产物与校验决定**。需要智能体或工具执行的阶段运行关联一个 PentAGI Flow，保存执行容器与实时轨迹；纯导入、规则计算与投影不强制创建 Flow。阶段与 Flow 通过显式映射关联。

| 入口 | 复用 PentAGI | 驱动方式 |
|---|---|---|
| 分步页面 | Flow 详情组件 | 用户手动触发单阶段，前置不足时提示补充 |
| 自动执行 | 自动 Flow（primary_agent + 规划/反思循环） | 编排器按 DAG 触发，遇人工点暂停 |
| 交互助手 | Assistant 链路 | 助手通过研究工具逐个驱动阶段 |

三种入口不得各自维护状态；助手模式下的产出同样落库落证据。

### 2.3 智能体与程序的分工（精度前提）


- **智能体**：规划、检索、非结构化解析、关联假设、能力选择、结果解释、任务调整建议、报告叙述。
- **程序**：版本/CPE/PURL 比较、去重合并、授权与范围校验、状态转换、证据判定、链路剪枝边界、评分计算、审批放行、报告装配与发布门禁。
- 智能体结论一律先落 `candidate`，由规则/证据/人工转 `confirmed`。

### 2.4 存储分层


| 层 | 存储 | 内容 | 一致性 |
|---|---|---|---|
| 结构化事实 | PostgreSQL（唯一事实源） | 项目/范围/资产/漏洞知识/条件/任务/状态/审批/证据元数据/报告快照/outbox | 单库事务；行带 `project_id`、`revision`、时间戳 |
| 图谱关系 | Neo4j（自有 schema） | 领域关系边（资产/组件/漏洞/条件/链/证据） | 由 outbox **确定性写入**，可用 PostgreSQL 全量重建 |
| 检索索引 | pgvector | 文档分块与向量（国标、公告、手册、上传资料） | outbox 异步生成，落后时界面提示 |
| 原始证据 | 文件 + SHA-256 | 扫描原始输出、公告快照、日志、截图、报告 | 写入即计算哈希，不可覆盖 |
| 智能体记忆 | Graphiti（按需）+ pgvector | 消息、经验记忆 | 现有逻辑不变 |

### 2.6 状态机（任务与阶段）


**阶段状态**（`research_stages.status`）

```
pending ──┐
ready ────┼─► running ─► succeeded ─► stale（上游重算）─► ready（重算）
stale ────┘        │
                   ├─► failed ─────────► ready（人工重试）
                   ├─► awaiting_input ─► ready（补充输入后）
                   ├─► awaiting_approval ► ready（批准后）
                   └─► blocked ────────► ready（前置修复后）
```

（`skipped` 未画入简化路径：仅当人工请求且服务确认该阶段可跳过时由 `ready` 进入并记录原因，之后可从 `skipped` 回到 `ready`；授权与审批校验不可跳过。`pending → ready` 表示依赖产物与修订已满足，与 `stale → running` 直连等价。）

**任务状态**（`research_tasks.status`）：`draft → queued → running →（completed ｜ awaiting_input ｜ awaiting_approval ｜ error ｜ paused ｜ terminated）`；`completed` 触发重算时**创建新的 `stage_run` 与 `OutputRevision`**（原完成运行与已发布快照保持只读，不复用），`paused` 可显式恢复到 `running`，`terminated` 是**不可逆终态**（继续工作需新建任务并关联原任务）；转移细节见 CONTRACTS §2.1/§2.2。

**不变式**

1. 只有编排器（`pkg/research`）写阶段状态；模型不能置位；
2. 每次执行新建 stage_run；每次状态转换在同一事务内写阶段状态、事件、必要审计和 outbox，终态同时写运行结果；
3. 缺有效授权时，A/S/V 中主动接触目标的动作置 blocked 且写 deny 审计，任务转 awaiting_input；离线导入只检查资料访问权限。阶段停止增加 cancelling/cancelled 状态，具体转移见 CONTRACTS §2.2；
4. 上游版本变化时，仅将依赖该版本的下游标为 stale；正在运行的下游先取消/失效，旧运行返回时不得覆盖新修订；
5. `succeeded` 必须经过服务层产物校验：有效输出修订、项目归属、证据存在、依赖修订一致。处理器返回成功只是候选执行结果。

### 2.7 三种入口如何落到 PentAGI


| 入口 | 落点 | 机制 |
|---|---|---|
| 分步页面 | 阶段服务 API | 页面按阶段调用 `research.Service`；前置不足时返回 `reason_code` + `next_actions`，不启动任务 |
| 自动执行 | 编排器 + 现有自动 Flow | 编排器按 DAG 触发；需要智能体/工具时创建 Flow 并记录映射；遇审批/冲突/反馈超限暂停；阶段作业存 research_jobs |
| 交互助手 | 现有 Assistant 链路 + 研究工具 | 新增 `run_stage`、`stage_status`、`match_vulnerabilities`、`propose_chain`、`request_verification` 等工具注册进现有工具注册表；助手驱动阶段，但产出同样落库落证据 |

三种入口都只调用同一个 `research.Service`，**都不直接写阶段状态**；因此演示时可以一键启动、中途接管、再回到助手追问，状态始终一致。

**执行对象映射（冻结约束，A-01 定稿）**

- 研究侧：`research_task` 是根，`research_stage` 是逻辑阶段，`stage_run` 是每次尝试；需要智能体或工具执行的 `stage_run` 关联一个 PentAGI Flow（纯导入、规则计算与投影不建 Flow），`flow_id`、可选 `assistant_id` 与策略版本记在 `stage_run` 上。
- 阶段内的 PentAGI `task`/`subtask`/`toolcall`/`msglog`/`termlog` 只作为该阶段的**只读执行轨迹**展示，不作为研究业务对象，也不作为阶段状态来源。
- **禁止以 PentAGI `subtask_id` 作为新表键或依赖边**：`RefineSubtasks` 会删除并重建计划行，id 不稳定。验证任务图与全部依赖关系存于新业务表，使用自有稳定标识。
- 证据二进制沿用现有 `pkg/flowfiles` 内容寻址存储，`evidence` 行保存 SHA-256、来源与解析版本；文件发布与数据库引用不在同一事务，按 §10 的恢复步骤处理。
- 阶段并发与现有作业执行器共存：研究阶段与知识采集/投影分配独立并发预算（§7），不占满执行槽。

### 2.8 权限与角色


- 复用现有 `roles`/`privileges`（Admin / User），按查询、编辑、执行、审批、审计、能力管理和发布行为新增 `research.*` 权限，其中**审批（`research.approve`）、审计（`research.audit`）、发布（`research.report.publish`）、能力管理（`research.capability.manage`）独立授权**，便于"可操作但不可审批"的部署。
- 审批规则由程序校验：审批人 ≠ 申请人；R3 需**两名不同审批者**；审批绑定目标 + 参数摘要 + 能力版本 + 有效期，任一变更即失效。
- 审计与业务日志分开存储；网关拒绝、越权判定、审批决定、证据访问、报告发布均入审计。

## 3. 阶段定义（输入/处理/输出/失败语义）


> 详细字段与 reason_code 见 `CONTRACTS.md`。此处只列关键约定。

### 3.1 K 漏洞收集与知识图谱（常驻）

- 输入：外部源（NVD/CISA KEV/MITRE ATT&CK/CWE/厂商公告）、用户上传资料、内部反馈事件。
- 确定性处理：增量同步、解析归一、实体归并、版本范围解析、来源冲突标记、原始快照与版本、关系边写入。
- 智能体：非结构化抽取、术语归一建议、冲突解释、知识缺口分析。
- 输出：漏洞知识修订、影响范围、条件/检测特征、设备检测约束、文档索引、图谱边。
- 失败语义：来源不可用 / 许可受限 / 解析未知 / 冲突待复核 / 索引落后 —— 全部显式呈现，不静默。

### 3.2 A 资产发现

- 输入：范围与授权、被动观测文件（Zeek 优先，pcap 补充）、台账/Nmap XML 导入、主动补全策略。
- 确定性处理：观测标准化、实体归并（强标识优先 + 候选评分 + 硬冲突禁止自动合并）、可达性判定、缺口清单。
- 智能体：缺口分析、补全方式选择（低交互优先）、结果解释。
- 输出：资产、标识、接口、服务、组件、观测、可达性、归并记录（可拆分回滚）。
- 失败语义：越权/受阻断、解析失败、部分完成、证据不足、字段未知（区分"未观察到/工具无响应/字段未知/人工确认不存在"）。

### 3.3 M 疑似资产-漏洞集合

- 输入：资产组件（含版本原文/归一/生态）、漏洞知识修订、既有适用条件证据。
- 确定性处理：CPE/PURL 匹配 → 版本范围判定 → 已有适用条件核验 → 缺口分类 → 候选状态机。
- 输出：候选记录（`to_detect` / `need_asset_attributes` / `excluded` / `need_review`）、检测要求、共享检测项、检测依赖。
- 失败语义：版本无法判定 → `unknown` 并生成补证，不猜测。

### 3.4 S 定向漏洞扫描

- 输入：待检测记录、检测能力（经审核）、执行约束（范围/频率/窗口）。
- 确定性处理：任务依赖、共享检测项合并、技能选择、执行、证据回填、检测覆盖快照、三态判定。
- 输出：Finding、资产-漏洞状态（`candidate`/`confirmed`/`not_detected`/`conflict`/`stale`）、原始证据。
- 失败语义：`not_detected` 只在覆盖完整时产生；部分执行只能得到 `candidate`。

### 3.5 R 利用链推理

- 输入：冻结事实快照（资产/漏洞状态/可达性/条件）、知识修订、搜索参数（版本化）。
- 确定性处理：子图提取、条件/效果规则校验、有界搜索、剪枝去环、签名去重、可信度与风险分项。
- 智能体：语义条件解释、未知条件补全建议（仅建议，不写入事实）。
- 输出：候选链、节点/边、依据、未知项、补证清单、终止原因、评分。
- 失败语义：无合法路径 / 超时截断 / 关键条件未知或冲突 / 数据过期 —— 均返回原因而非静默漏链；关模型仍能生成路径。

### 3.6 V 多 Agent 受控验证

- 输入：经复核候选链、验证任务图、授权与审批、环境证明、能力版本。
- 确定性处理：依赖调度、网关复核、受控执行、前中后基线、证据判定、七类结论、反馈事件。
- 智能体：能力选择与排序、失败归因、结论解释、任务调整建议。
- 输出：四类事实（条件/执行/效果/约束）、执行记录、验证结论、知识反馈事件。
- 失败语义：等待审批 / 受约束阻断 / 执行失败 / 证据不足 / 已停止或恢复失败 —— 与"条件不成立"严格区分。

### 3.7 反馈与限次

- 反馈事件记录触发者、受影响事实/链/任务、重算范围；依赖追踪保证只重算受影响子图；
- 默认最大反馈轮次 3，每轮要求增量有效信息，超限转人工确认；所有轮次在任务时间线可见。

### 3.8 P 报告输出

- 输入：冻结数据快照、审核状态、模板版本。
- 确定性处理：字段装配、引用校验、脱敏、快照与版本、发布门禁。
- 智能体：有引用的叙述撰写（必须带 evidence id）。
- 输出：中文报告、证据附录、整改建议、复测比较；状态：草稿/审核中/已发布/复测版。
- 失败语义：缺证据禁止发布、数据过期需重算、审核退回、导出失败。

- **能力策略**：接通 Functions.Disabled 兼容旧调用；研究任务额外使用服务端生成的显式允许集合，缺少策略则拒绝执行。所有代理/助手继承同一请求范围；新增工具不会因为未在禁用列表中就自动获准。
- **审批**：`approvals` 绑定请求内容（目标 + 参数摘要 + 能力版本 + 有效期）；参数/策略变更即失效；R2 单审、R3 两名不同审批者；支持撤回与紧急停止。
- **执行边界**：PentAGI 进程内的容器命令面由三处组成——`docker/client.go:433` 起的 `ContainerCreate`（容器的启动命令）、`:907` 的 `ContainerExecCreate` 与 `:915` 的 `ContainerExecAttach`（配套使用；现有调用方为 `terminal.go:225/269`、`tools.go:656/665`、`flow_files.go:1336/1345`），网关必须整体覆盖，新增通路也要经网关。**但这不等于"容器命令唯一出口"**：`DOCKER_INSIDE=true` 且未设 `DOCKER_INSIDE_HOST` 时，宿主 `docker.sock` 会被 bind-mount 进 worker 容器（`pkg/docker/client.go:337-342`、`Config.WorkerDockerSocket()`），容器内进程可直接访问 Docker daemon 绕过上述三处。因此研究 runner 的硬约束是：不挂载完整 socket（`DOCKER_INSIDE=false` 且不设 `DOCKER_SOCKET`），确需容器化能力时改用受限 Docker API 代理，网关是唯一签发者。socket 挂载分三种情况：PentAGI 应用容器固定挂载宿主 socket（`docker-compose.yml:206,211`），worker 容器仅在 `DOCKER_INSIDE=true` 且未设 `DOCKER_INSIDE_HOST` 时挂载（`pkg/docker/client.go:337-342`），研究 runner **禁止挂载**。容器以 root 运行，不能当作权限边界。
- **出站限制（E 阶段主动扫描前必须完成）**：按任务创建的独立 Docker 网络只解决任务之间不串扰，**不限制公网、宿主和局域网访问**。主动能力放行前必须在宿主侧实现出站策略：目标 IP/CIDR、端口与协议白名单（由 §11.2 范围判定结果生成）、DNS 解析结果与被连接地址一致、重定向与重连再校验、越界即拒并写审计。
- **输入安全**：外部资料、工具输出、MCP 返回一律按数据（不可信）处理，不得改写策略/状态或触发新调用。

## 10. 工程约束与迁移方式


当前以单套应用为开发目标，历史部署入口为 http://localhost:8443。靶场位于独立环境，本轮不部署靶场。代码使用本地分支管理；Neo4j 按 C 阶段配置加入现有配套服务，并把现有 graphiti compose 栈（`docker-compose-graphiti.yml`）中的 neo4j 拆为常驻启动单元（D14），不新建第二套应用。

- 固定 Go、sqlc、前端生成工具版本并记录实际可用运行方式；可复用 Docker 工具链。原文“本机无 pnpm”等只属于当次观察，不作为永久约束。版本必须落在仓库内可执行入口（脚本或 Makefile），不能只写在说明文档的命令示例里——当前 sqlc 1.27.0 仅出现在 `README.md` 与 `backend/docs/database.md`。
- sqlc 当前配置含 database.uri；分析库必须与目标迁移一致，实际解析路径和版本兼容性通过生成零差异及新查询测试确认，不笼统承诺仅依赖真实库。
- goose 解析文件名首个下划线前的数字作为版本，因此现有 YYYYMMDD_HHMMSS 形式把"同一天的第二个迁移"变成版本冲突风险（当前 32 个文件的日期版本互不重复，尚未触发）。新迁移采用唯一的 YYYYMMDDHHMMSS 前缀（14 位，如 `20260916100000_research_core.sql`），同日可以多批。历史文件 `20250103_1215631_*.sql` 的时间位是 7 位笔误，但它位于版本号之后的名称部分，不影响 goose 解析（版本仍取 `20250103`），仅作命名记录。实施前列出所有解析版本检查重复与排序，示例日期不是排期承诺。
- 每批先在指定测试库走当前版本升级与空库安装，再测试该批回退/再升级及跨项目约束。历史 assistants Down 顺序尚未修复，应单独提交修正和测试；未涉及历史版本的批次回退不必全库 reset。
- 新迁移会随应用启动自动执行，因此仅在当前批次通过验收后进入部署。已产生用户数据后优先采用兼容旧读路径和向前修复；没有备份时不能把破坏性 Down 当作无损回滚。
- PostgreSQL 与文件无法一个事务提交：文件发布/元数据引用/孤立对象清理需有恢复步骤；已有证据不得覆盖或以级联删除移除。
- outbox 按项目/实体修订防止乱序覆盖；向量/图索引返回来源版本，落后时使用明确版本的 PostgreSQL 快照或显示重算/等待，不能混读。
- 新增 GraphQL/SQL 通过现有生成流程更新；文件路径与执行命令在相关脚本落地后补入导读。
- 工程回归和独立授权环境中的集成验证继续执行；它们不是被后置的科研对照实验。

### 11.2 规则与资源边界


- 版本：采用 CPE 2.3/PURL 标识与产品别名，SemVer/Debian/RPM 使用生态比较器；缺省 epoch 按生态定义处理，不把正常省略误当错误；不支持的厂商版本返回 unknown。测试开闭区间、修复版本、预发行与冲突来源。
- 归并：强标识必须带网络/厂商/时间上下文，MAC 不能独自证明同一设备；保留观测和合并操作，硬冲突进入复核，可按原始观测拆分。
- 搜索：暂定深度 5、每节点分支 20、束宽 100、路径最多 2 个未知条件、最多 100 条结果、30 秒时限及扩展节点上限；稳定排序和版本化参数保证可复算。墙钟截断可能使结果子集不同，记录部分结果与终止点，不能声称截断运行必得相同全集。
- 状态：推演路径的预期效果只进入路径假设集合；验证获得的直接观察才能成为实际事实。未知条件不能被效果假设悄悄替换。
- 反馈：默认最多 3 轮，必须有新证据/知识修订；限预算、限窗口、记录受影响依赖，没有增量转人工。
- 采集：先 Zeek 离线日志；pcap 转换受限运行并保留工具版本，Suricata/实时抓包按后续能力扩展；不从出现过通信推断任意方向的当前可达性。
- 向量：只向量化允许外发的文档块，CVE 等结构化数据以字段查询为主；业务审计日志避免存凭据，原始证据按权限保留。
- 报告：保存已审核的模型正文与确定性事实快照；断模型重建表示可导出相同保存内容，不要求重新生成同样的自然语言。
