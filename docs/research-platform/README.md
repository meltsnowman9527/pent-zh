# 研究平台后续开发文档

当前实施依据为 [PLAN.md](PLAN.md)，数据与执行契约见 [CONTRACTS.md](CONTRACTS.md)。

## 1. 保留的讨论方向

漏洞收集与知识图谱 → 资产发现与定向扫描 → 利用链推理 → 多智能体受控验证 → 报告输出。手动页面、自动执行、交互助手驱动同一研究任务。

保留 Neo4j 自有领域图谱与可视化、PostgreSQL 唯一事实源、Graphiti 按需记忆、Zeek 日志优先、用户配置 Skill/MCP、按风险审批、限次反馈、精度优先、软著材料同步。靶场在独立环境，本轮不部署；科研实验与统计后置。

## 3. 后续从哪里开始

按 [PLAN §9](PLAN.md#9-后续开发顺序与交付要求) 执行：

1. A：公共契约、核心迁移、证据、阶段服务、持久调度和能力策略。
2. B：五页与任务中心，三入口共用服务。
3. C：漏洞知识采集、Neo4j 投影和图谱。
4. D：Zeek/台账导入、资产归并、版本比较与候选匹配。
5. E：受控扫描、能力配置及覆盖判定。
6. F：有界利用链推理、评分和补证。
7. G：多智能体验证、审批/反馈、MCP 接入。
8. H：报告快照、复测、整体回归及软著材料。

A-01 至 A-07 已在方案中列明依赖、交付物和验收。领域表随相应服务/API/页面交付，不以一次建满全部表作为开工条件。

## 5. 验证方式

后续每批运行实际存在的构建/生成/测试入口。迁移助手和演练脚本目前尚未创建，其设计要求见 PLAN §10；脚本落地验证后再补可复制命令。

需要覆盖数据库升级与批次回退、跨项目权限、状态并发/取消、证据完整性、审批与目标范围、图索引版本、规则夹具及现有功能回归。外部授权环境用于扫描/验证集成测试，离线夹具不能冒充实际执行验收。
